# 출결 관리 프로그램

첨부된 출결 규정을 기준으로 회원별 출결을 입력하고, 저장할 때마다 실제 Excel 통합 파일과 Excel/Google Sheets 호환 CSV 파일로 자동 동기화하는 로컬 웹 프로그램입니다.

## 실행

```bash
cd /Users/jl/Desktop/CAMI/attendance
python3 server.py
```

브라우저에서 [http://127.0.0.1:8000](http://127.0.0.1:8000)을 엽니다.

## 자동 연동 파일

- `data/attendance.csv`: 행사·회원별 상세 출결 기록
- `data/attendance_summary.csv`: 월별 참여율, 기준 충족 여부, 누적 경고, 벌금 요약
- `data/attendance.xlsx`: `출결기록`, `월별요약` 두 시트가 들어 있는 Excel 통합 파일
- `data/state.json`: 프로그램의 원본 저장 데이터

프로그램에서 출결, 회원, 행사를 저장하면 Excel 통합 파일과 두 CSV 파일이 함께 갱신됩니다. CSV 파일은 Excel 또는 Google Sheets로 바로 열 수 있습니다.

회원 정보에는 이름, `기수`, `비고`를 저장하며, 모든 회원이 기수를 입력할 수 있습니다. 비고에서 `운영진` 또는 `일반 회원`을 선택할 수 있고, 운영진을 선택하면 `총괄`, `정보`, `홍보`, `총무`, `출결` 중 부서를 선택할 수 있습니다. `정보` 부서는 최대 2명까지 등록됩니다. 출결 기록은 `출석 시간`, `이달의 누적 출석`, `전체 누적 출석`으로 표시됩니다.

새 회원 ID는 자동 생성되며 운영진은 `O-`, 일반 회원은 `M-`으로 시작합니다.

## GitHub 공개 페이지

`public/` 폴더는 수정 기능이 없는 공개 확인용 페이지입니다. GitHub Pages는 Python 서버를 실행하지 않으므로, 이 페이지는 `public/data/public-state.json`이라는 공개용 스냅샷만 읽습니다.

로컬 출결 프로그램에서 회원·행사를 저장하면 공개용 스냅샷도 함께 갱신됩니다. Excel 파일을 정리한 뒤 아래 파일을 GitHub에 커밋하고 push하면 공개 페이지가 업데이트됩니다.

```text
public/data/public-state.json
```

GitHub 저장소의 Pages 설정에서 `GitHub Actions`를 배포 방식으로 선택하면 `.github/workflows/pages.yml`이 `public/` 폴더를 자동 배포합니다. 공개 저장소에는 회원명과 출결 현황이 보일 수 있으므로, 외부 공개가 곤란한 개인정보는 공개 데이터에 포함하지 않도록 확인해야 합니다.

## 대시보드와 회칙

로컬 관리자와 공개 페이지 모두 `출석률 | 이달의 출석왕 / 출석규정 | 이번달 일정`의 2열 카드 배치를 사용합니다. 좁은 화면에서는 한 열로 표시됩니다. 규정 카드를 펼치면 전달받은 회칙 전문을 읽을 수 있습니다.

- 월별·전체 출석률은 각각 50% 이상을 기준으로 합니다.
- 출석왕은 해당 월 인정 출석횟수 기준이며 동률은 공동 수상입니다.
- 확정한 월의 출석률 미달이 2개월이면 출석경고 누계 1회, 3개월 이상이면 2회입니다. 같은 활동기간 안에서만 합산합니다.
- 공식행사 1회, 조건을 모두 충족한 번개 0.5회, 대표 대외활동 예외 0.5회 등의 회칙은 규정 전문에 안내합니다.
- 벌금 5개 항목, 수료실패 후 활동 유지 시 2배, 정기출사 적용범위와 사전공지 예외도 전문에 포함합니다. 월별 출결표의 0·1 값으로 지각·무단결석·벌금을 추정하지 않습니다.

## 월별 출결표 반영

1. 로컬 대시보드 하단의 **월별 출결표 가져오기**를 펼칩니다.
2. `.xlsx` 파일, 활동기간(예: `21기`), 대상 월을 입력하고 **미리보기**를 누릅니다. 같은 활동기간은 동일한 이름을 사용합니다.
3. 행사 일정, 회원별 집계, 원본의 행사별 값과 집계 간 차이를 확인합니다.
4. 회원 연결이 완료된 뒤 집계 및 해당 월 출결 확정을 체크하고 **이 달 반영**을 누릅니다. 같은 달의 재반영은 기존 월별 집계를 교체합니다. 반영 전 데이터는 `data/backups/`에 보관합니다.

지원 형식은 제공받은 `출결표` 시트의 행사표(B3 성명/출사지), 하단 집계(C64 성명), 번개 일정(M열), 외부행사 일정(AC열)입니다. 월별로 분리된 파일을 사용하며 다른 달의 날짜가 섞인 파일은 반영하지 않습니다. 집계 수식은 실행하지 않고 Excel에서 마지막으로 저장된 값을 읽습니다. 수식 결과가 없으면 Excel에서 재계산하고 저장해야 합니다.

출석률 계산에는 하단 집계의 전체횟수(D열), 참여횟수(E열), 번개 인정횟수(G열)를 사용합니다. 번개 참석자 명단만으로 인정 조건을 추정하지 않습니다. 외부활동(H열)이 있으면 회칙에 맞는 인정 단위를 확인할 때까지 반영을 보류합니다. 행사별 출석값과 집계값이 다르면 차이를 명시하고 집계 기준을 확인한 뒤 반영합니다. 회원의 월 출석률은 100%를 넘을 수 있으며 값을 임의로 줄이지 않습니다.

기본 회원 명단은 제공받은 CSV 기준으로 확정했습니다(`rosterReady: true`). 총 28명 중 활동회원 27명과 휴학 1명이며, 운영진 6명의 부서와 각 회원의 기수를 반영했습니다. 기존 회원 ID와 출결 기록은 보존합니다. 새 명단에 없는 기존 인원은 로컬 이력으로만 보관하고 공개 명단 및 집계에서 제외합니다. 휴학 회원은 명단에 표시하되 출석률·출석왕 및 경고 집계에서 제외합니다.

9월 월별 집계 27명을 반영했습니다. 이진욱 회원의 행사별 합계와 하단 집계가 달랐던 항목은 사용자 확인에 따라 참여횟수 1회로 정정했고, 정정 근거를 해당 집계의 `correction`에 보관합니다. 원본 CSV와 Excel은 변경하지 않았습니다. 회원 연결 전 데이터는 `data/backups/before-member-roster.csv-import.json`에 보관되어 있습니다. 동명이인과 미등록 회원이 있으면 월별 반영을 막습니다.

검증: `python3 -m unittest discover -s tests -v`
